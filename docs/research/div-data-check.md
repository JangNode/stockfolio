# 배당 데이터 가능성 점검·수집 계획 (DV1·DV1C 시험용, 시험 아님)

연구 브랜치 `claude/ma-v3-portfolio-cap-run` 전용. 사용자 지시 2026-11-28. main 병합·변경·운영 적용·PR·pg_cron 없음. **이 문서의 점검 기준은 호출 전에 커밋한다**(결과를 보고 바꾸지 않는다). 구현: `scripts/collect-div.ts`(D_MODE=pilot|collect), 기준값 `lib/dividendConfig.ts`, 워크플로 `which=vequity`·`only=divpilot|divcollect`.

## 1. 쓰려는 API
DART 오픈API **배당에 관한 사항(alotMatter.json)**: 요청 = corp_code · bsns_year · reprt_code(사업보고서 11011). 응답 항목 = 접수번호(rcept_no) · 구분(se: 주당 현금배당금(원) 등) · 주식 종류(stock_knd: 보통주/우선주) · 당기(thstrm)·전기(frmtrm)·전전기(lwfr). 접수번호는 YYYYMMDD + 일련번호 형식이라 앞 8자리가 접수일이다(점검에서 확인).

## 2. 1단계 점검 설계(저장 없음, 로그 표만)
- **표본 30개사**: 지정 6개(보통주·우선주가 모두 있는 삼성전자 005930·현대차 005380, 금융지주 KB금융 105560·신한지주 055550, 지주사 SK 034730·LG 003550) + 소멸 4개(마지막 가격 행 2012-04-01~2016-04-30) + 시총(2011-12 말) 구간 층화 20개(0~500억 7 · 500~2,000억 6 · 2,000~5,000억 4 · 5,000억 이상 3), 시드 20261128. 모집단 = 기존 재무 백필과 같은 종목(2011-03~2016-04 월말 구간 후보, 우선주·ETF·SPAC·리츠 제외, corp_code 매핑 있음, 약 2,127개사).
- **호출**: 회사당 alotMatter × 사업연도 2011~2025(15회) + list.json(정기공시, 정정 표기·원본 접수일 확인) 1~2회 ≈ 480~520회. DART 호출은 이 두 API만, 연구용 키(DART_API_KEY_3 → _2)만, **키당 하루 16,000건(일일 한도 20,000건의 80%) 이내**, 실패는 재시도(2회, 지수 대기), status 020이면 키 전환, 모두 한도면 멈춘다.
- **확인 항목**: ① 호출당 몇 개 연도가 오는지(당기·전기·전전기 값 필드) ② 접수일을 접수번호에서 알 수 있는지 ③ 정정 공시 때 값이 바뀌는지(list.json의 정정 사업보고서와 비교, 다음 해 보고서의 전기값과의 일치) — 정정 전 원본 값을 얻을 수 없으면 한계로 기록 ④ 우선주·보통주 구분(stock_knd) ⑤ 배당 0 또는 무배당 표기(숫자 0, "-", 빈칸) ⑥ 기대(그 사업연도 말 전에 가격 행이 있고 다음 해 3월 말까지 이어진) 회사-연도 대비 보통주 주당 현금배당금 숫자 값 확보율.
- **전체 호출 수·시간 추정**: 점검에서 잰 분당 호출 수로 본 수집(약 2,127개사 × 15개 사업연도 + list.json)의 호출 수·소요·필요 일수를 계산한다.

## 3. 판정 기준(점검 전에 고정, `DIV_PASS`)
다음 네 가지를 모두 만족하면 통과, 하나라도 못 미치면 **멈추고 보고**한다.
1. 호출 1회로 당기 값과 접수번호가 온다(응답에 당기·전기·전전기 필드가 있는 보통주 주당 현금배당금 행이 있다).
2. 접수번호 앞 8자리가 유효한 날짜(YYYYMMDD)다(접수일을 알 수 있다).
3. 기대 회사-연도 대비 **보통주 주당 현금배당금 숫자 값 확보율 ≥ 70%**.
4. 전체 호출이 키 일일 한도(80%) × 키 2개 안에서 **2일 이내**에 끝난다(그보다 길면 사용자 확인).

## 4. 2단계(통과 시에만) 계획
- 대상: 위 모집단 전체(소멸 포함), 사업연도 2011~2025. 저장: **Storage `research/dividend/dividend.parquet` 1개**(종목, 사업연도, 보통주 주당 현금배당금(당기)·원표기, 우선주 값, 전기·전전기 값, 접수번호·접수일, list.json 원본 접수번호·정정 여부) + `_progress.json`(이어받기). 새 파일은 50 MiB 이내(예상 수 MiB). Actions 아티팩트 업로드 없음, 키 값 출력 없음, 연구 DB 쓰기 0.
- 호출: alotMatter 회사 × 사업연도 + list.json 회사당 1~2회. 일일 한도 80%(키당 16,000건)를 넘기지 않고, 소프트 마감 170분마다 저장·종료, 한도 초과·status 020이면 멈추고 다음 날 이어서(이어받기).
- 수집 후 보고: 종목·연도 커버리지, 월말(BS1 적격) 기준 배당 데이터 계산 가능 비율.

## 5. 한계(미리 공개)
alotMatter는 회사·사업연도·보고서 종류만 받아 **최신 접수본**을 돌려주므로 정정 전 원본 값은 얻을 수 없다(접수번호가 원본이 아니면 그 접수일을 써 PIT는 안전하게 늦게 반영하되 값은 정정값일 수 있다). 대상은 기존 재무 백필과 같은 종목(2016-04 이전 월말 구간 후보)이라 **2016-05 이후 신규 상장 종목은 배당 데이터가 없다**(월말 계산 가능 비율에 반영, 시험 유니버스 편향으로 사전등록에 공개). 사업보고서 이전의 결산·분기 배당(중간·분기 배당)은 사업연도 합계에 포함되는지 점검에서 확인하지 못할 수 있다.
