# 연구 PEAD 잠정실적(영업(잠정)실적 공정공시) 이벤트 가능성 점검 + 파일럿 — 사전등록 초안

작성 2026-10-28(사용자 지정). **이 문서는 시험이 아니다.** 가능성 점검과 파일럿 결과, 그리고 "승인 시 시험 설계안"만 적는다. 시도 번호는 소진하지 않았고 누적은 240이다. 가격 성과(수익률·CAGR·MDD)는 계산하지 않았고, 통과 판정도 하지 않는다. 대량 수집·시험은 사용자 승인 전에는 하지 않는다. 연구 브랜치 claude/ma-v3-portfolio-cap-run에서만 작업하고 main 병합·운영 적용·PR은 하지 않는다.

## 0. 동기

연구 PEAD(235~240)의 이벤트는 정기보고서(분기·반기·사업) 접수일이다. 영업(잠정)실적 공정공시는 같은 분기 실적이 정기보고서보다 먼저 나오므로, 같은 규칙을 "더 이른 접수일"에 적용하면 드리프트의 앞부분을 쓸 수 있는지 확인할 가치가 있다. 이 가설은 PEAD 결과(PE1 지연 민감, 게이트 C 탈락)를 본 뒤 세웠다.

## 1. 점검 조건 (지킨 것)

DART는 연구용 키 두 개(DART_API_KEY_2/_3)만 사용(운영 키 미사용, 키 값 비출력). 연구 DB 쓰기 0, Storage 쓰기 0, 가격 Parquet 다운로드 0(고정 스냅샷 `parquet-snapshot-20261026` 캐시 적중), 14:00~15:40 KST KIS·KRX 호출 없음, 원문 문서 저장 없음(파싱 값과 짧은 발췌만 로그). 점검 호출 수: 1차 65 + 2차 96 + 3차 27 = **188건**(2·3차 합계 123건, 키별 번갈아 사용). 연구 R 기록상 누적 8,403건에 더하면 8,591건.

## 3. 결과 2 — 파일럿 (문서 호출 20건: 코스피 14 + 시각 문맥 재조회 3 + 코스닥 3, 원문 비저장)

- **크기**: 코스피 14건 zip 합계 34,618 B(평균 2,473 B), 압축 해제 약 1.3~2.0만 자, 파일 1개. 단위: 백만원 12 / 억원 2(LX인터내셔널 등) → **단위 혼재가 있으므로 문서 머리의 "단위 :" 표기를 읽어 정규화해야 한다**.
- **구조**: 표가 셀 한 줄씩 나열되는 형태(열: 당기실적 | 전기실적 | 전기대비증감율 | (흑자적자전환여부) | 전년동기실적 | 전년동기대비증감율 | (흑자적자전환여부)); 행: 매출액 / 영업이익 / 법인세비용차감전계속사업이익 / 당기순이익, 각 행에 당해실적·누계실적 하위 행. 흑자적자전환 열이 있는 문서와 없는 문서가 섞여 있어 **헤더로 열 역할을 판별**해야 한다. 1차 휴리스틱 파서는 0건 추출(0%), 토큰 기반 파서로 바꿔 오프라인에서 코스피 14건 모두 파싱 가능을 확인했다(이 파서는 시험 전 확정이 아니라 파일럿용이다).
- **연결/별도**: 제목이 "연결재무제표기준영업(잠정)실적" 또는 "영업(잠정)실적"(별도). 파일럿 코스피 14건은 연결 12 + 별도 2(JW생명과학, 대한전선). 정기보고서 이벤트(fin.parquet)는 연결 우선이라, 같은 기준으로 맞출 규칙이 필요하다(8절 결정 3).
- **정기보고서(DART 단일회사 재무 API fnlttSinglAcnt) 값과 비교**(당기·전년동기 분기 영업이익 모두 일치 기준): 코스피 **11/14 일치(78.57%)**. 불일치 3건: 국도화학 2020 Q2(공정공시 15,408 vs API 15,452 백만원), KT&G 2016 Q4(공정공시 304,949/263,852 vs API 303,682/264,282 백만원; Q4는 사업 연간 − 3분기 누계로 유도한 값이라 비교 자체의 오차 가능), HD현대 2023 Q1(6,109억 vs API 5,334억; 엔티티·연결 범위 차이 가능성). 원인은 더 파지 않았다. **잠정치는 확정치와 다를 수 있다는 문구가 문서에 있다**(금호석유화학 등).
- **코스닥 3건**: 제노레이 2020-08-05 파싱 실패(값 7개 vs 헤더 5열), 에스앤에스텍 2023-04-20(파싱 6,997/3,545 vs API 5,900/3,399 불일치), 에스앤에스텍 2025-04-23(11,939/7,369 vs 10,510/5,755 불일치). 표본이 3건이라 코스닥 파싱률·일치율은 판단할 수 없다.

## 4. 결과 3 — 접수 시각·장중/장마감 정보

문서 본문에 접수 시각, 장중/장마감 구분은 **없다**. 본문의 "11:30", "오전 9시", "16:00" 같은 시각 문구는 모두 기업설명회·컨퍼런스콜의 "정보제공(예정)일시"이고 공시 접수 시각이 아니다(확인: 20170119800060, 20190802800010, 20230427800350 맥락 재조회). 목록 API의 rcept_dt도 날짜(YYYYMMDD)뿐이다. 따라서 **현재 정의(접수일 다음 거래일 신호 확정, 그다음 거래일 종가 체결)를 그대로 쓸 수 있고 더 보수적으로 바꾸지도 않는다**. 장중·장마감 구분이 불가능하므로 같은 날 반응 일부가 접수일 종가에 이미 반영됐을 수 있는 한계는 정기보고서 이벤트와 같다. 정정 공시는 이벤트에서 제외한다(정기보고서 때와 같은 "원본만" 규칙).

## 6. 승인 시 시험 설계안 (승인 전에는 실행하지 않음, 가격 성과 계산 없음)

**후보 1개(PE7, 시도 241 — 승인 시 소진) + 보유 이웃 2개(시도 아님, 게이트 D 전용).**

- **PE7**: PE4와 같다 — 유니버스 K200P, 영업이익 전년 동기 대비 증가율 ≥ 30%, 보유 20거래일, 신호 확정일 = 접수일(비거래일이면 그 뒤 첫 거래일)의 다음 거래일, 체결 = 신호 확정일 다음 거래일 종가, 신호 확정일 종가가 접수일 종가보다 높을 때만 매수, 증가율 큰 순 선택, 슬롯 10 × 10%, 재진입 금지 20거래일, 비용 0.015%/편도 + 매도세, 슬리피지 0.1%, 코스피 보통주 PIT, 상장폐지 강제 청산, 국내 주식 + 현금만. PE4와 다른 점은 **이벤트 소스뿐**: 같은 기업·같은 분기의 (정기보고서 원본, 잠정실적 원본) 중 **접수일이 더 이른 쪽 하나**를 이벤트로 쓴다. 한 기업·분기 이벤트는 하나만 만든다(잠정실적 + 정기보고서로 두 번 진입하지 않는다).
- **이웃(게이트 D)**: 보유 10·30거래일만(증가율·기타 파라미터 이웃 없음, 추가 파라미터 탐색 없음). 이웃 2개 모두 전체 구간 CAGR ≥ 069500이면 D = O. (기존 게이트 D는 증가율 ±10%p 이웃도 포함했으나 이번에는 사용자 지시로 보유 이웃만 쓴다 — 정의 변경이므로 승인 때 확인.)
- **영업이익 값의 우선순위**: 이벤트가 잠정실적이면 잠정실적 문서의 당기·전년동기 분기 영업이익(당해실적 행)을 쓴다. 정기보고서 이벤트이면 기존 fin.parquet 값. 잠정치와 확정치가 다를 수 있다는 점은 한계로 기록한다.
- **게이트·구간**: 게이트 A~H 기존 정의 그대로, 기준선 069500(2017-04-04 시작 새 기준선: 전체 12.20 / 42.03, 학습 1.47 / 25.95, 확인 15.72 / 34.75, 보류 17.31 / 42.03), G 100건 완화 금지, B는 세 구간 중 2개, 게이트 F 무작위 풀·1,000회·시드 20261022(풀에 잠정실적 이벤트 포함), H는 069500과 PE4 재계산값 모두 표시하고 069500 기준 판정. 통과 = A~H 전부 O. 통과해도 운영 적용·PR 금지, 통과하지 못해도 원인을 파지 않고 결과만 보고한다.
- **누적 시도 번호 영향**: 승인 시 241(1개). 기대 우연 통과 수 241 × 0.05 = 12.05.
- 그 밖: 시험 전 이 문서에 결정 사항을 추기해 커밋하고 해시를 보고한다. 후보당 한 번만 실행하고 결과를 본 뒤 정의·게이트를 바꾸지 않는다.

## 7. 한계 (알려진 것)

1. 건수 추정은 표본 분산이 커 신뢰구간이 넓다(연도별 20~110% 편차).
2. 파일럿 표본이 코스피 14건·코스닥 3건뿐이라 파싱 성공률·일치율은 대략치다.
3. 코스피 11/14 일치(78.57%): 일치하지 않은 경우의 원인(공시 후 확정치 차이, Q4 유도 오차, 연결 범위)은 구분하지 않았다.
4. 접수 시각이 없어 장중·장마감 구분 불가(정기보고서와 같은 한계).
5. 잠정실적과 정기보고서의 영업이익이 다르면 같은 분기에 서로 다른 증가율이 나오며, 가장 이른 쪽만 쓰는 규칙은 선택 편향이 없는 사전 규칙이지만 잠정치 노이즈가 신호에 섞인다.
6. 2017-01-01 이전 잠정실적은 수집 범위 밖(2011~2015 원문 수집 금지는 유지).

## 8. 승인 시 결정해야 할 사항 (권고 포함, 사용자 결정 전 확정 아님)

1. **수집 범위**: 코스피만 vs 코스피 + 코스닥. 권고: 코스피 K200P 유니버스만 시험하므로 코스피만(약 18.9k 호출). 코스닥은 파싱 실패·불일치가 확인돼 별도 점검 후.
2. **파싱 실패율 허용 기준**: 예) 열 역할 판별 실패·당기/전년동기 값 누락 문서는 이벤트에서 제외하고, 제외율이 일정 수준(예: 10%)을 넘으면 시험 중단. 값 일치 검증(정기보고서 값과의 비교)을 시험 전에 전수로 할지, 하지 않고 79% 일치를 한계로 받아들일지.
3. **연결/별도 선택**: 연결 우선(정기보고서 이벤트와 동일), 없으면 별도. 한 기업·분기에 연결·별도가 둘 다 있으면 연결 사용 / 접수일이 이른 쪽 사용 / 연결만 사용 중 선택.

5. **Storage**: fin.parquet 재읽기 없이 부분집합 캐시로 진행할지(5절).

### 9.1 수집 범위와 저장
- **코스피만**(corp_cls=Y), 거래소공시(pblntf_ty=I) 중 제목에 '영업(잠정)실적'이 있는 공시, 접수일 2017-01-01~2026-10-26. 코스닥은 수집하지 않는다.
- **정정 공시 제외**(제목에 '정정' 또는 '첨부추가'). **연결 우선**: 같은 기업·기간에 연결 문서가 하나라도 있으면(파싱 실패한 것 포함) 별도 문서는 이벤트에 쓰지 않고, 연결이 없을 때만 별도를 쓴다. 같은 종류가 여러 개면 접수일이 이른 것(같은 날이면 접수번호 순). 규칙 구현: `lib/peadPrelimSelect.ts`.
- 원문은 저장하지 않는다. 저장 항목: 기업코드, 종목코드, 접수번호, 접수일, 제목, 연결/별도, 당기 영업이익, 전년 동기 영업이익(둘 다 **원 단위로 통일**, 표기 단위 억원·백만원·만원·천원·원을 환산), 표기 단위, 기간(연도·분기)과 그 출처, 파싱 성공 여부와 실패 사유, zip 크기. 저장 위치는 Actions 캐시(research-prelim-parsed-<run id>)와 아티팩트이며 Supabase 쓰기는 0이다.
- 호출: DART 연구용 키 `DART_API_KEY_2/_3`만, 키당 일 18,000건 상한, 호출 간격 120 ms, 일꾼 4개(키당 2). 문서별 **3회 재시도**(지수 백오프), 그래도 실패하면 **실패 목록**에 기록하고 이벤트에서 제외한다(실패 건은 이어받기 실행으로 한 번 더 시도). 기존 저장분(접수번호)은 덮어쓰지 않고 없는 것만 받는다. 키 한도로 못 받은 문서가 남으면 시험하지 않는다.
- **파서**(`scripts/collect-pead-prelim.ts`의 `parseDoc`): 표를 셀 단위 토큰으로 읽어 첫 '영업이익' 행의 '당해실적' 다음 값 칸을 모은다. 값 칸이 5개면 [당기, 전기, 전기대비, 전년동기, 전년동기대비], 7개면 전기대비·전년동기대비 뒤에 흑자적자전환여부 칸이 하나씩 더 있는 배치([당기, 전기, 전기대비, 전환, 전년동기, 전년동기대비, 전환])로 읽는다(7개일 때 전환 칸이 숫자이면 배치를 잘못 읽은 것이라 실패로 처리). 그 밖의 칸 수, 영업이익 행 없음, 단위 불명, 당기·전년동기 값 누락(대시 등)은 파싱 실패다. 기간은 머리글의 첫 기간 표기(당기)에서 읽는다(`periodFromLabel`: '23년 2분기, 2018.4Q, 19년 반기, 2023.7.1~2023.9.30, 2Q23, Q3.'19 등). 해석하지 못하거나 그 기간의 끝(12월 결산 가정의 분기말)이 접수일보다 뒤인 표기(표기 오류)이면 접수 월로 추정한다(1~3월 = 전년 4분기, 4~6월 = 1분기, 7~9월 = 2분기, 10~12월 = 3분기; 출처 inferred). **월 단위 표기('2022년11월' 등)는 분기 실적이 아니라 period_q = 0으로 두어 이벤트 선택에서 제외**한다. 이 파서는 가능성 점검 파일럿 14건의 발췌로 확인했고, 대량 수집 전에 연도별 층화 표본 파일럿(`PCOL_SAMPLE=1`, 연 40건)으로 한 번 더 확인한다(수정은 수집 시작 전까지만, 가격 자료는 보지 않는다).

### 9.2 데이터 품질 문턱 (시험 전 확정, 변경 금지)
1. **파싱 실패율**(열 판별 실패·값 누락·단위 불명·행 없음 문서 ÷ 받은 문서 전체) **10% 초과이면 시험하지 않고 중단·보고**한다. **'값 누락'은 글자 그대로 센다**: 영업이익 행의 당기 또는 전년 동기 칸이 대시·비숫자인 문서는 모두 실패다(영업이익을 공시하지 않아 행 전체가 대시인 문서, 전년 동기 칸만 대시인 문서 포함). 영업이익 미공시 문서를 뺀 비율은 참고로만 병기하고 판정에는 쓰지 않는다. 글자 그대로의 비율이 10%를 넘으면 시험 없이 수집 결과만 보고하고, 정의를 바꿔 진행할지는 사용자 결정에 맡긴다.
2. **전수 대조 일치율**: 기업·기간당 선택 문서(연결 우선) 중 파싱 성공 문서의 당기 영업이익을 같은 기업·분기 정기보고서 값(fin 부분집합; 연결=CFS·별도=OFS, 사업보고서 4분기는 연간 − 3분기 누적)과 비교해 **오차가 정기보고서 값의 1% 이내 또는 표기 단위 1개 이내이면 일치**로 센다. 정기보고서 값이 없는 문서는 분모에서 뺀다(건수는 보고). **일치율 70% 미만이면 시험하지 않고 중단·보고**한다. 불일치는 기계적 규칙으로 '파싱 오류 의심'(부호 반전, 자릿수 10^k배 차이, 정기보고서의 누계 또는 전년 값과 일치)과 '잠정·확정 차이 의심'(차이 30% 이내), '기타'로 나눠 각 대표 예 3건씩 보고하고 **원인은 더 파지 않는다**.
3. **이벤트 신호는 문서에 적힌 당기·전년 동기 값만** 쓴다(확정치로 보정하지 않는다).
4. 두 문턱은 시험이 아니라 수집 데이터에 대한 점검이며 가격 성과를 보지 않고 판정한다. 문턱 미통과 시 시험 없이 수집 결과만 보고한다.

### 9.3 PE7 정의 (시도 241, PE4와 모두 같고 이벤트 소스만 다름)
- 유니버스 K200P(코스피 보통주 시총 상위 200), 분기 영업이익 > 0 ∧ 전년 동기 > 0 ∧ 증가율 ≥ 30%, 신호 확정일 = 접수일(비거래일이면 그 뒤 첫 거래일)의 다음 거래일, 체결 = 그다음 거래일 종가, 신호 확정일 종가가 접수일 종가보다 높을 때만 매수, 체결 후 20거래일이 지나면 다음 거래일 종가 매도, 증가율 큰 순 선택, 슬롯 10 × 10%, 재진입 금지 20거래일, 비용 0.015%/편도 + 매도세, 슬리피지 0.1%, 상장폐지 강제 청산.
- **이벤트 소스**: 같은 기업·기간의 정기보고서(원본)와 잠정실적(원본) 중 **접수일이 더 이른 쪽 하나만** 이벤트로 쓴다. 둘 다 있으면 늦은 쪽은 신호로 쓰지 않는다. 접수일이 같으면 정기보고서. 한쪽만 있으면(유효한 값이 있는 것만) 그것을 쓴다. 기간 키 = 회사|사업연도|분기(정기보고서는 보고서 종류로, 잠정실적은 9.1의 기간으로 정한다. 12월 결산이 아닌 법인의 기간 표기는 맞지 않을 수 있다 — 한계).
- 평가 구간·기준선은 PE4와 같다: 수익 집계 2017-04-03, 학습 2017-04-03~2019-12-31 / 확인 2020~2021 / 보류 2022~, 069500 보조 파일 기준 전체 12.20 / 42.03.
- **게이트 A~H 기존 정의 그대로**(G 100건 완화 금지, B 세 구간 중 2개 이상). **게이트 D 이웃은 원래 정의로 복원**: 증가율 20%·40%와 보유 10·30거래일 모두(4개; 6절의 '보유 이웃만' 안은 철회). 게이트 F 무작위 풀은 PE4와 같은 방식이며 같은 소스 규칙을 적용한 이벤트 집합(그날 유니버스 안 비교 가능한 원본 접수 이벤트 중 접수일 종가 대비 상승, 영업이익 조건 없음), 1,000회, 시드 20261022. 게이트 H는 069500과 PE4(재계산, 기존 14.21 / 23.99)를 모두 표시하고 **069500 기준으로 판정**한다(조건1: CAGR ≥ 069500 + 1%p, 조건2: MDD ≤ 069500 − 3%p ∧ CAGR ≥ 069500 − 1%p).
- 통과 = A~H 전부 O. 통과해도 운영 적용·PR 금지, 통과하지 못해도 원인을 더 파지 않고 결과만 보고한다. 결과를 본 뒤 정의 변경·재실행 금지(단, 결과가 하나도 출력되기 전에 코드 오류로 중단된 경우에 한해 정의를 바꾸지 않고 오류만 고쳐 다시 실행할 수 있으며 보고에 밝힌다).
