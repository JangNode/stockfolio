## 1. 외국계 창구 일별 매매

### 1.1 API 사실 (확인된 것과 아닌 것)
| 항목 | 내용 | 상태 |
|---|---|---|
| TR | `/uapi/domestic-stock/v1/quotations/inquire-member-daily`, TR_ID `FHPST04540000`("주식현재가 회원사 종목매매동향 일별") | 확인(2026-11-05 점검) |
| 요청 | `FID_INPUT_ISCD` = **종목코드**, `FID_INPUT_ISCD_2` = **회원사 코드**(점검에서 `99999`), `FID_INPUT_DATE_1~2` = 조회 기간, `FID_COND_MRKT_DIV_CODE=J`, `FID_SCTN_CLS_CODE` 공란 | 확인 |
| 종목 단위인지 시장 단위인지 | **종목 단위**(종목코드가 필수). 시장 합계 호출 방법은 확인된 적 없음 | 확인 |
| 창구(회원사) 수 구분 | **호출 하나 = 회원사 코드 하나**. `99999`는 KIS 문서상 외국계 합계로 알려진 코드로 쓰지만 **의미는 추정**(수집 파일럿에서 외국인 투자자 순매수와 부호·규모를 대조해 확인, 사전등록 7절) | 응답 필드는 확인, 코드 의미는 미확인 |
| 응답 필드 | 날짜별 매도 수량, 매수 수량, 순매수 수량, 종가 | 확인(점검 응답 키 요약) |
| 깊이 | 2011-01-03까지 확인(2011-01 범위 21행). 최근 1개월 23행 | 확인 |
| **호출당 행 수** | **미확인**. 월 범위에서 21~23행이 모두 나왔으므로 상한은 23 이상. 연 범위로 부른 적 없음 | **미확인** |
| 값의 성격 | 수량은 원 주수(분할 미조정), 종가는 원주가. 같은 날 값을 곱해 금액으로 만든다 | 확인(점검 필드·단위 요약) |
| 장 종료 후 확정 | 일별 행은 장 종료 후 확정 값이라 신호일 d의 값은 d+1 종가에 체결(체결강도와 같은 규칙) | 가정 |

### 1.2 호출 수·소요 시나리오
대상 = 4-A와 같은 420종목 목록(월말 PIT 시총 상위 150에 한 번이라도 든 종목, 상장폐지 포함). 학습 구간(2011-01-03~2016-12-29, 거래일 1,482일)에 가격이 있는 종목은 **344개**(4-A 실제값). 소요는 4-A 실측 호출당 **0.432초**(4,745건 34.2분)로 계산. 범위 분할은 행 상한의 90%(30행→27행, 100행→90행씩, 연 범위 상한이면 연 단위).

| 구간 | 대상 종목 | 호출당 30행 | 호출당 100행 | 연 범위 이상(≥250행) |
|---|---|---|---|---|
| **학습** 2011-01~2016-12 | 344 | 18,920회 · 2.27시간 | 5,848회 · 0.70시간 | 2,064회 · 0.25시간 |
| 전체 2011-01~2026-10 | 420 | 60,480회 · 7.26시간 | 18,480회 · 2.22시간 | 6,720회 · 0.81시간 |
| 2단계(확인·보류) 2017-01~2026-10 | 420 | 37,380회 · 4.49시간 | 11,340회 · 1.36시간 | 4,200회 · 0.50시간 |
- 회차는 최대 4.75시간(기존 방식)이라 학습 구간은 어떤 시나리오에서도 1회차에 끝난다(30행이면 2.3시간). 전체 구간이 30행이면 2회차가 필요하다.
- 요청 누적 상한은 **파일럿으로 확정한 중심값의 1.3배**로 정한다(4-A는 예상 5,300 + 시장 34의 1.3배인 7,000건이었고 실제 4,745건).
- 파일럿(승인 후 첫 단계, 호출 3~4회): 삼성전자 `FID_INPUT_ISCD_2=99999`로 (a) 2011년 1년 범위, (b) 2013년 1년 범위를 불러 호출당 행 수를 확정하고(행이 250 안팎이면 연 범위 가능, 그보다 작은 값에서 끊기면 그 값이 상한), (c) 2011-01 범위를 다시 불러 21행 재현을 확인한다. 상한에 걸린 경우 응답 날짜 범위(끝·시작)로 어느 쪽부터 잘리는지 확인해 분할 규칙을 정한다(대차 파일럿과 같은 방식: 연 범위가 최근 쪽 N행만 줌).
- 분할 규칙(상한 확정 뒤): 종목별 조회 구간을 거래일 달력 기준으로 상한의 90% 크기 조각으로 나눠 부르고, 어떤 조각이 상한과 같은 행 수를 주면 그 조각을 반으로 나눠 다시 부른다(행 누락 방지, 호출 수는 위 표보다 최대 3% 늘 수 있음).
- 상장폐지 종목: 이 TR에서 확인된 적 없음(체결강도는 44/48 포함 확인). 파일럿에 폐지 종목 1개(한진해운 등 4-A 대상에 포함된 폐지 종목 코드 하나) 1회를 포함한다(호출 +1).

### 1.3 저장·정리본 용량
- 저장 열(Parquet, 종목코드·날짜 + 숫자 4개): 매수 수량, 매도 수량, 순매수 수량, 응답 종가(가격 Parquet과 대조용). 4-A 체결강도(숫자 2열) 정리본이 약 10 B/행이었으므로 4열 약 14~16 B/행으로 추정.
- 학습 구간 행 수 약 46만(4-A 체결강도 460,559행과 같은 규모) → 정리본 약 6.5~7.5 MiB, 원본 포함 쓰기 **약 12~16 MiB**. 전체 구간은 약 2.6배로 약 32~42 MiB(후보가 나온 뒤 2단계 수집을 할 때만).
- 진행 파일(`_progress.json`) 약 0.03 MiB 이하.

### 1.4 이어받기·중단·정리본
- 4-A 수집기(`scripts/collect-scan4a.ts`) 구조를 그대로 쓴다: 단일 워커 순차 호출, KST 14:00~15:40 호출 금지(시작 시·매 요청 전 확인), rate limit 5/15/60초 재시도, 연속 오류 20건 중단, 종목 20개 또는 20분마다 체크포인트, 진행 파일 + 연도별 Parquet로 이어받기, 키 `(종목, 날짜)` 병합.
- 정리본: 거래일 달력 밖 제거, 중복 제거, 가격 Parquet 종가와 응답 종가 대조, 모든 값이 0인 종목·가격은 있는데 값이 없는 날 비율 계산, 매니페스트 SHA-256. 수집 작업 끝에서 Storage와 **Actions 캐시·아티팩트에 함께 저장**해 스캔은 Storage를 읽지 않는다.
- 새 수집기 파일명(제안): `scripts/collect-scan5.ts`(외국계 창구 + 대차 한 파일, 모드 `fm`·`loan`·`pilot`), 설정 `lib/scan5Config.ts`, 워크플로 옵션 `scan5`(수집)·`scan5s`(스캔). 승인 전에는 만들지 않는다.

## 2. 대차잔고 (종목 단위, 4-B 계획 재정리)

- API: `daily-loan-trans`(HHPST074500C0), `MRKT_DIV_CLS_CODE=3`(종목), 기간 범위. **호출당 100행 확정**(2014·2015년 1년 범위 모두 100행에서 끊김, 연 범위는 구간의 **최근 쪽** 100행을 준다). 종목 단위 시작은 **2014-08-04까지 직접 확인**(2013년 범위 0행, 2014년 범위의 가장 이른 날 2014-08-04, 그 앞은 100행 상한에 잘려 미확인).
- **구간(수집 전 고정, 4-B 초안 그대로)**: 수집 시작 2015-01(2015-01 이전 값은 쓰지 않음) / **학습 2015-04-01~2019-12-31** / 확인 2020-01-01~2021-12-31 / 보류 2022-01-01~.
- 호출 수(4-B 계획 그대로, 100행/호출): 학습 수집(2015-01~2019-12) 약 **4,300회**(상한 5,500회), 소요 **약 0.52시간**(4,300) ~0.66시간(5,500)(0.432초/호출). 이전 문서의 "0.6~0.8시간"은 호출당 0.5초 가정이었고 4-A 실측으로 갱신. 행 약 41만, 정리본 약 4~5 MiB, 원본 포함 쓰기 **약 8~10 MiB**.
- 2단계(확인·보류, 후보가 나온 뒤만): 약 6,000회(상한 7,600), 약 0.7~0.9시간, 쓰기 약 11~16 MiB.
- 신호는 4-B 초안 그대로: **L1 대차잔고율**(잔고 수량 ÷ 상장주식수), **L2 대차잔고 20일 변화율**, 사용일 j = c − 2(2거래일 전까지의 값, 최대 5거래일 이어 쓰기). 사전등록 5회차 문서에 옮겨 고정한다.
- **2014-01~07 미확인 구간 확인(11-14 이후, 호출 1~2회)**: 삼성전자 `MRKT_DIV_CLS_CODE=3`, ① 2014-01-01~2014-07-31 1회. 행이 0이면 시작은 2014-08(확정). 행이 있으면(최근 쪽 100행 상한에 걸리면 2014-03 이후부터 100행이라는 뜻이므로) ② 2014-01-01~2014-04-30 1회로 가장 이른 날을 확인. **이 확인은 정보용**이다: 결과가 어떻든 수집 시작(2015-01)·학습 구간(2015-04-01~2019-12-31)·신호 정의는 바꾸지 않는다(결과를 보고 구간을 바꾸는 사후 변경 방지).
- 파일럿(승인 후 첫 단계, 호출 2회): 삼성전자 2015년 1년 범위로 100행·최근 쪽 절단 재확인, 폐지 종목 1개 1회(대차는 폐지 종목 조회 미확인 항목).
- 대상 종목: 4-A와 같은 420종목 목록에서 2015-01~2019-12에 가격이 있는 종목(약 330~380개, 파일럿 직전에 가격 스냅샷으로 계산).
- 편향·시차: 대차 잔고는 결제 이후 확정되는 값이라 신호일 2거래일 전까지만 사용(신용잔고와 같은 보수 규칙, 공개 시차는 확인할 수 없음).

## 4. Storage 예산 (새 청구 주기 가정: 읽기 누적 0에서 시작, 쓰기는 현재 저장 총량 기준)

### 4.1 쓰기(① 저장 총량, 800 MiB 가드)
- **현재 저장 총량 약 444 MiB**(2026-11-05 4-A 수집 직후 443.98 MiB + VKOSPI 정리본 0.14 MiB = 약 444.1 MiB).

## 5. Actions 캐시 만료와 DS6 포워드 캐시 상태 확인·재읽기 판단 (11-14 첫 승인일 묶음)

### 5.1 문제
Actions 캐시는 **7일 동안 쓰이지 않으면 삭제**된다. 마지막으로 캐시를 복원한 실행은 2026-11-05~06(UTC)의 VKOSPI·DS12 실행이므로 **약 2026-11-12~13에 지워질 수 있고, 11-14 이후 승인 시점에는 이미 없을 가능성이 크다**. 영향받는 캐시:

### 5.2 11-14 이전 선택지 (사용자 판단 필요, 11-11까지)
- **A. 캐시 유지 실행 1회(권장)**: 11-10~11-11에 `which=ds12 only=repro`(1.3분, 이전에 성공한 사전 점검)를 한 번 실행한다. 복원되는 캐시(스냅샷·보조 파일·일별 순수익·VKOSPI)의 만료 시계가 새로 시작된다. Storage 읽기 0.21 MiB(월말 시장 목록, **현재 청구 주기**에 들어감), KIS·KRX 호출 0, DART 0, DB 쓰기 0. 효과: 11-14 이후 231 MiB 재읽기 회피. 이 실행은 승인이 있어야 하며 **승인이 없으면 하지 않는다**.
- B. 아무것도 안 함: 11-14 이후 캐시가 없으면 스캔·포워드 게이트가 막히고(4-A처럼 Storage 읽기 0으로 중단) 231 MiB 재구축은 별도 승인이 필요하다. 새 주기 읽기 예산에는 여유가 있다(4.2절 최악 약 313 MiB).

### 5.3 11-14 이후 첫 승인일의 순서 (한 날에 묶음)
1. **캐시·아티팩트 상태 확인**(`pclean only=list`, 연구 DB·Storage 접근 없음, 호출 0): 위 6개 캐시와 아티팩트 보존 여부.
2. **DS6 포워드 재읽기 판단**: 스냅샷·보조 파일 캐시가 살아 있으면 포워드 로그 갱신 실행(KRX 호출 약 신규 거래일 수만큼, 읽기 약 15.3 MiB, KST 14:00~15:40 금지). 만료되어 있으면 **재구축 여부를 사용자에게 묻고**(스캔 5-A·5-B에도 같은 스냅샷이 필요하므로 한 번 재구축하면 둘 다 해결), 승인 없이 231 MiB를 읽지 않는다.
3. 신용잔고 정리본 한 번 읽기(약 20.6 MiB) → Actions 캐시·아티팩트 저장(6절).
4. 파일럿(외국계 창구 4회, 대차 3~4회) → 호출 수 확정 → 승인 범위 확인.
5. 수집: 외국계 창구 학습 → 대차 학습(각 회차 끝에 정리본 Actions 캐시 저장). 6. 스캔 5-A·5-B 각 1회(학습 구간만).
- 한 번에 한 회차만(KIS 토큰 하나), 모든 KIS 호출은 KST 15:45 이후 시작.

## 6. 신용잔고 정리본 읽기 (같은 날 묶음)

## 7. 편향·시차 (정의에 반영)
- 외국계 창구: 장 종료 후 확정 값(신호일 d 값까지 사용, d+1 종가 체결). 대차: 신호일 2거래일 전까지의 값.
- 대상은 "월말 시총 상위 150에 든 적 있는 종목"뿐이라 POOL(상위 100)은 완전하고 MID는 시총 101~150위(이전 스캔 1~3회차의 MID와 직접 비교 불가).
- 외국계 창구 99999의 정확한 의미는 추정이므로 정의 고정 후에도 수집 파일럿과 사전등록 7절의 대조 점검에서 확인한다(맞지 않으면 스캔하지 않고 숫자만 보고).
- 외국계 창구는 증권사 창구 기준(외국계 증권사를 통한 주문)이고 외국인 투자자 수급은 KRX 투자자 구분 기준이라 같은 양이 아니다. 두 값의 차이(FMD)가 한 신호다.

## 8. 이번 계획에서 뺀 것 (이유)
- **상위 몇 개 창구의 쏠림 정도(창구별 집중도)**: 개별 외국계 창구 코드 목록과 창구별 계열의 호출당 행 수가 확인된 적 없고, 창구 N개를 받으면 호출이 N배(예: 학습 구간·연 범위 상한 기준 2,064회 × N)다. 승인 후 파일럿에서 현재 거래일 회원사 순위 TR(`inquire-member`, 점검한 적 없음) 1~2회로 코드 목록만 확인하는 별도 가능성 점검을 하고, 가능하면 **별도 사전등록(5-C)**으로 다룬다. 이번 사전등록의 외국계 신호 3개는 99999 한 계열만 쓴다.
- 시간외·분봉·옵션 신호는 해당 없음.

## 9. 승인 때 확인할 것
1. 11-11까지 캐시 유지 실행(5.2절 A)을 할지.
2. 11-14 이후 첫 승인일 묶음(5.3절)의 순서와 범위(파일럿 호출 약 10회 포함).
3. 외국계 창구를 99999 한 계열만 수집하는 것(쏠림 신호 제외)으로 충분한지, 5-C 가능성 점검을 따로 할지.
4. 새 청구 주기의 읽기 상한(600 MiB 가정이 맞는지)과 DS6 포워드 실행 빈도.
5. 요청 누적 상한(파일럿 확정 중심값의 1.3배)과 회차 4.75시간 규칙 유지 여부.
6. 수집기·워크플로 옵션(`scan5`, `scan5s`)을 만들어도 되는지(수집 실행은 별도 승인).
