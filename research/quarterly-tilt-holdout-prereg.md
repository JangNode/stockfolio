## 1. 홀드아웃 정의 (사용자 지정 원문)
- 대상: Q3(research/quarterly-tilt-prereg.md bec9a35의 정의 그대로, S_OP 틸트, 5·8·11월 말 리밸런스). 정의·파라미터 변경 금지.
- 홀드아웃 기간: 2011-06-01~2016-05-31. 비교: 같은 기간 POOL, D4, KOSPI(같은 비용).
- 기준: H1 CAGR > POOL, H2 CAGR > D4, H3 MDD ≤ POOL MDD + 3.0%p, H4 CAGR÷MDD > POOL, H5 +1거래일 지연 시 CAGR 하락 ≤ 1.0%p. 전부 O일 때만 통과. 누적 시도 +1.
- 정보용(기준 아님): 005930·005935·000660 제외 시 Q3와 POOL, S_OP 스피어만 상관과 5분위별 다음 달 수익률, 연도별 초과수익, POOL 대비 베타와 베타 조정 초과수익(연, 일수익 회귀로 산출).

### 홀드아웃 구현 보충 (실행 전에 고정)
1. 규칙은 bec9a35와 같다: 풀 = 그날 PIT 적격(직전 행 시총 ≥ 5000억 + 당일 `avgTv` ≥ 5억) 중 당일 시총 상위 100 시총 비례, 틸트 상위 k=floor(n/5) ×2 · 하위 k ×0.5(n<5이면 틸트 없음), 리밸런스 5·8·11월 마지막 거래일, 비용·강제 청산·엔진 동일, 첫 리밸런스는 2011-05 월말(수익률은 2011-06-01부터, 초기 진입 비용은 평가 구간에서 빠짐). 데이터 규칙(off_cycle 제외, 접수일 ≥ 분기 말, 접수일 당일 종가 이후 사용, 150일 신선도, 가장 최근 분기만 사용)도 그대로.
2. 4분기 파생 레코드는 홀드아웃에서 만들지 않는다. 이유: Q3는 S_OP만 쓰고 4분기 영업이익은 없다. 리밸런스일이 5·8·11월 말이고 접수일 최신 레코드 기준이라 4분기 레코드(연간 보고서, 보통 3월 접수)가 5월 말의 1분기, 8월 말의 반기, 11월 말의 3분기 레코드보다 최근이 되는 경우는 해당 분기 레코드가 없거나 제외된 때뿐인데, 그때도 3월 접수 4분기는 더 오래된 레코드(150일 신선도 밖이거나 같은 "데이터 없음")와 결과가 같다. 따라서 홀드아웃 신호는 XBRL(FY2011~2015)·singl(FY2016) 1~3분기 레코드만으로 정의한다.
3. 홀드아웃의 마지막 리밸런스(2016-05-31)는 FY2016 1분기(singl 행)를 쓴다. 평가 구간 안의 경로는 이 리밸런스 이전까지의 비중만 사용한다.
4. D4·POOL은 2011-05 월말부터 새로 시작해 같은 엔진·비용으로 계산한다. KOSPI는 가격지수 일 수익률을 같은 구간으로 자른 값. 지표 정의(CAGR/MDD/연변동성/회전율/비용)는 bec9a35 보충 9항과 같다. H5의 하락 = (기본 CAGR) − (지연 CAGR).
5. 정보용: ① 005930·005935·000660을 풀에서 처음부터 제외한 Q3·POOL의 CAGR/MDD ② S_OP 스피어만 상관(월 평균·t값)과 5분위별 다음 달 평균 수익률(bec9a35 보충 12항 정의, 홀드아웃 구간의 월말) ③ 연도별 수익률과 Q3−POOL, Q3−D4(2011은 6월부터, 2016은 5월까지) ④ 베타·베타 조정 초과수익: 홀드아웃 일 수익률에서 r_Q3 = α + β·r_POOL을 OLS로 적합, 연 α = (평균 r_Q3 − β·평균 r_POOL) × 252 (%, 산술).
6. 시도 횟수: 홀드아웃 실행 때 누적 시도 +1(97 → 98). 이번 백필 단계에서는 올리지 않는다.

## 2. 백필 대상과 경로 (사용자 지정 요약 + 보충)
- 대상: dart_quarterly_fundamentals 백필과 같은 종목 집합(PIT 진입 이력 + corp_code 보유, 상장폐지 포함, 상장 기간 밖 연도 제외). FY2011~FY2015 1분기·반기·3분기, 검증용 FY2016 같은 분기(저장하지 않음).
- 종목당 list.json(pblntf_ty=A, page_count=100, 끝까지, 조회 기간 2011-04-01~2016-12-31 한 번)로 분기보고서·반기보고서의 rcept_no를 찾는다. 보고서명 `분기보고서 (YYYY.03)`=1분기, `반기보고서 (YYYY.06)`=2분기, `분기보고서 (YYYY.09)`=3분기. ## 3. 추출 규칙 (실행 전에 고정)
1. **컨텍스트 순서**: 연결(`ConsolidatedMember`) → 차원 없음 → 별도(`SeparateMember`). 한 보고서(행)에서 NI·영업이익·매출의 3개월 컨텍스트 중 하나라도 존재하는 첫 종류를 그 행의 기준으로 쓰고, 모든 항목을 그 기준 안에서만 찾는다(없으면 null). fs_div: 연결 → `CFS`, 별도 → `OFS`, 차원 없음 → `null`(기준은 account_ids_used에 `basis=cons|nodim|sep`로 기록). 차원 구분은 `lib/dartXbrlExtract.ts`의 `ctxKind`를 쓴다.
2. **기간**: 분기 말 E = `FY-03-31`(1분기), `FY-06-30`(반기), `FY-09-30`(3분기). 3개월 = 끝 E이고 시작~끝 80~100일인 컨텍스트 → `*_q`. 누적 = 시작이 `FY-01-01`이고 끝 E → `*_cum`. 전년 같은 분기 3개월 = 끝 E−1년(같은 월일)이고 80~100일 → `*_prev_q`. 전년 누적 = 시작 `(FY−1)-01-01`이고 끝 E−1년 → `*_prev_cum`. 1분기는 3개월 = 누적(`*_cum = *_q`, `*_prev_cum = *_prev_q`). 12월 결산이 아닌 종목은 해당 컨텍스트가 없으면 null.
3. **계정**(태그의 local name 기준, 접두사 무관): 순이익 `ProfitLossAttributableToOwnersOfParent`, 해당 기준의 3개월 컨텍스트에 없으면 `ProfitLoss`(ni_tag = parent / profitloss, 네 값 모두 같은 태그). 영업이익 `OperatingIncomeLoss`(dart:). 매출 `Revenue`(ifrs:). 자본(분기 말 시점, 시작일 없는 컨텍스트, 끝 = E) `EquityAttributableToOwnersOfParent`, 없으면 `Equity`. 같은 컨텍스트·태그에 팩트가 여럿이면 문서 순서상 첫 번째. 못 찾으면 null.
4. **저장**: `dart_quarterly_fundamentals`에 같은 컬럼으로 저장, 새 nullable 컬럼 `source`('singl'|'xbrl')를 추가하고 기존 행은 'singl'로만 채운다(다른 기존 값은 바꾸지 않는다). `status`는 ok / no_report(list.json에 해당 분기 보고서 없음) / xbrl_014(fnlttXbrl가 014: 파일 없음) / error(그 밖의 DART 오류 코드, XBRL에 대상 팩트가 전혀 없음, 압축 해석 실패). 기존 CHECK 제약은 `status` 허용값에 no_report·xbrl_014를 추가하는 것으로만 바꾼다(기존 값은 모두 그대로 허용). `off_cycle` = 접수월이 1분기 5월, 반기 8월, 3분기 11월이 아님. `account_ids_used`는 `xbrl;ni:<태그>;rev:<태그|no_match>;op:<태그|no_match>;eq:<태그>;basis=<cons|nodim|sep>` 형식.
5. **FY2016 검증용 값은 저장하지 않는다**(메모리에서만 비교).

## 4. 1회차 맨 앞 검증 (고정)
- 표본: FY2016에 singl `ok` 행이 하나 이상 있는 대상 종목 중 시드 20261018(mulberry32, corp_code 오름차순 Fisher–Yates)로 30종목. 각 종목의 FY2016 1분기·반기·3분기 중 singl `ok` 행이 있는 분기만 XBRL로 받는다.
- 비교 항목 4개: `op_income_q`, `op_income_prev_q`, `ni_parent_q`, `ni_parent_prev_q`. 비교 대상 셀 = singl 값이 null이 아닌 셀. 불일치 = XBRL 값이 null이거나 |차이| > 1원. 불일치 비율 = 불일치 셀 ÷ 비교 대상 셀(4항목 합산). **5%를 넘으면 백필을 시작하지 않고** 항목별 비율·불일치 사례(종목·분기·두 값·사용 컨텍스트)를 보고하고 멈춘다. singl 값이 null인 셀은 비교에서 제외하고 건수만 보고한다.
- 검증은 이미 `source='xbrl'` 행이 하나라도 저장돼 있으면 건너뛴다(1회차만).
- 검증에 쓴 요청(list.json·fnlttXbrl)도 해당 실행의 요청 상한에 포함한다.

## 5. 한계 (미리 공개)
XBRL 인스턴스의 태그·컨텍스트 구조가 연도·공시 시스템에 따라 다를 수 있어 일부 항목은 null일 수 있다. 차원 없음 기준 행은 fs_div가 null이다. 판정·추천 없음.
