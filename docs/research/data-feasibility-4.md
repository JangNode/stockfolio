# 데이터 가용성 점검 4 — 저평가(가치) 지표용 KIS 데이터 (연구 묶음 5 블록 D, 시험 아님, 시험 번호 305 유지)

연구 브랜치 `claude/ma-v3-portfolio-cap-run` 전용. 2026-11-18 KST, KIS 호출 **20회**(상한 20; 1차 13회 + 후속 4회 + 후속 2차 3회), 저장 없음(Storage·연구 DB 쓰기 0), 공시(DART) 사용 없음, 키 값 출력 없음. 실행: 1차 run 44187492338(07:12 KST), 후속 44188044612(07:15), 후속 2차 44199942568(08:31).

## 0. 결론 (먼저)
- **판정: 현재 확인 범위에서는 PER·PBR·배당수익률 전략의 과거 시점(point-in-time) 검증용 데이터로 "사용 불가"다.** 핵심인 **재무 이력(BPS·EPS) 호출이 3번의 실행에서 모두 실패**해 이력 깊이·필드·발표 시점·상장폐지 종목 재무를 하나도 확인하지 못했다. 확인한 것은 상장·폐지 날짜, 배당 일정, 현재가의 현재 값뿐이다.
- 실패는 시간대 때문이 아니다(07:12·07:15·08:31 KST 동일). 20회 상한을 다 써서 더 부르지 않았고, 원인은 **미확인**이다.
- 배당은 쓸 수 있는 경로가 보인다(§4). 과거 재무 이력은 **KIS 재무 API가 다시 응답할 때** 소량(약 5회)으로 재확인하면 된다(§8).

## 1. 재무비율 이력(`finance/financial-ratio`, FHKST66430300): 실패
| 호출 | 결과 |
|---|---|
| 삼성전자 연·분기, SK하이닉스 연, KB금융 연, 한진해운·웅진에너지·페이퍼코리아 연 (1차) | **7회 모두 HTTP 404**(본문 없음) |
| 삼성전자 연 (후속 2차, 다른 시간대) | HTTP 404 |
- 요청 형식은 운영 코드(`lib/kis.ts`)의 다른 재무 호출과 같다(헤더 `custtype: P`, 파라미터 `FID_DIV_CLS_CODE`·`fid_cond_mrkt_div_code`·`fid_input_iscd`). 404는 이 경로·TR이 이 환경에서 제공되지 않거나 경로가 다르다는 뜻일 수 있으나 **원인은 확인하지 못했다.**
- 서드파티 블로그 한 곳(AlgoLab)은 이 TR이 EPS·BPS·주당매출을 주고 PER·PBR는 주지 않는다고 설명한다. **KIS 공식 문서로는 확인하지 못했다**(미확인으로 둔다).

## 2. 대차대조표·손익계산서(운영 코드와 같은 경로·TR): 실패
- `finance/balance-sheet`(FHKST66430100)을 삼성전자 연·분기, 한진해운 연으로, `finance/income-statement`(FHKST66430200)를 삼성전자 연으로 호출 → 후속·후속 2차 합계 **6회 모두 "호출 전처리 오류 입니다."**(`rt_cd` 비정상).
- 운영 코드는 같은 경로·TR·파라미터로 이 API를 부른다(`getBalanceSheetYears` 등). 따라서 **운영에서도 같은 오류가 나는지 별도로 확인할 필요가 있을 수 있다**(이 연구의 범위 밖이라 호출하지 않았다; 관찰만 기록).

## 7. 전 종목 호출 수·시간·용량 추정 (재무 API가 응답한다는 가정, 추정 — 확인 전)
- 대상: 월말 PIT 시총 상위 150 이력 약 420종목(상장폐지 48 포함, 폐지는 재무 조회 가능 여부 미확인).
- 재무비율 연 + 분기 = 종목당 2회 → **약 840회**(연만이면 420회). 이전 실측 순차 평균 0.7~1.1초/호출 기준 **약 10~15분**.
- 배당: 종목별 장기 조회 420회, 또는 전 종목 주간 창(약 15년 ≈ 780창, 한 창이 한 페이지를 넘으면 더 필요).
- 용량: 종목당 연 15~20행 + 분기 60~80행 정도(추정) × 약 10필드 → **1 MiB 안쪽**(Parquet 압축 전 기준 추정). 월 증분은 무시할 수 있는 크기. 규칙 3(용량 예산)은 문제 없다.
- 호출 한도: KIS 앱키 한도 안에서 순차 호출(기존 도구와 같은 호출 간격)로 충분하다.

## 8. 보수적 지연 규칙(제안, 발표일 필드가 없을 때)
재무 값 `stac_yymm`(결산월)을 판단일 t에 쓰려면 **법정 제출기한 뒤**에만 쓴다: 1·2·3분기(결산월 3·6·9월)는 분기 말 + 45일, 4분기(사업연도)는 결산월 말 + 90일, 다시 + 1거래일. 12월 외 결산 종목은 같은 일수를 그 결산월 기준으로 적용한다. 정정공시로 값이 바뀐 경우를 막으려면 **각 결산월에 처음 관측한 값만 저장**(변경점 저장 패턴)해야 하나, 과거 값을 한 번에 받는 방식에서는 이를 보장할 수 없다 → 과거 이력으로는 선견 위험이 남는다.
- 사용 불가 사유: 발표일 필드 없음 + 사후 수정 여부 미확인 + 이력 깊이 미확인 + 폐지 종목 재무 미확인.

## 9. 다음 단계 (제안만, 새 호출·구현 없음)

3. 과거 이력이 막히면 **포워드 스냅샷 수집** 제안: 월 1회 372종목 현재가(PER·PBR·EPS·BPS) 호출 372회(약 5분, 용량 무시) — 이 데이터는 앞으로만 쌓이므로 검증까지 몇 년이 걸린다(수집은 사용자 지시 전에 하지 않는다).
