# [임시 진단 — 병합 금지, 새 시도 아님] W2 peg 수치 불일치 원인 진단: 정의만

실행 **전에** 커밋한다. 판정·기준을 새로 만들지 않고 숫자와 표만 보고한다. 외부 요청 0건, DB 쓰기 0건, 재실행 1회만, 캐시 엄격 게이트(17개 연도 파일), main 변경 없음. peg 파라미터·규칙은 커밋 edb53b6(`scripts/research-peg-extended.ts`)와 같은 코드를 쓴다(재무 로더 조합만 바꾼다).

## 정의
- 변형: A = stock_annual_fundamentals만, B = A + fill(ok), C = A + dart_xbrl_fundamentals, D = 3표 합집합(우선순위 stock > fill > xbrl, edb53b6과 동일). 모두 W2(시작 2021-03-01, 끝 데이터 끝)로 `runBacktest`를 돌린다. 집계 시작 S(변형별) = 해당 변형의 첫 매수일이 속한 달 1일(edb53b6과 동일). 참고로 A를 시작 인자 2010-01-01로 돌린 값(A2010, 이전 검증과 같은 방식)도 계산한다.
- 거래 비교(A vs D): 같은 종목이고 매수일·청산일이 모두 같으면 "동일", 한쪽에만 있고 상대에 같은 종목의 보유 구간(매수일~청산일)이 겹치는 거래가 없으면 "D에만"/"A에만", 같은 종목 보유 구간이 겹치지만 날짜가 다르면 "날짜 다름"(A측·D측 건수를 각각 적는다).
- 기여 추정 = 그 거래의 일별 수익률(비용 반영) ÷ 그날 해당 변형의 보유 종목 수를 모든 보유일에 걸쳐 단순 합산한 %p.
- 일별 차이 = D 일별 수익률(%) − A 일별 수익률(%). 기여 종목 = 그날 (D에서의 종목 기여 − A에서의 종목 기여) 절댓값 상위 3개.
- D가 A보다 누적 수익이 낮아지는 구간 = 2021-03-01부터의 누적 수익률 차이(D−A, %p) 시계열에서 고점→저점 하락폭이 가장 큰 구간(고점일~저점일). 그 구간의 일평균 보유 종목 수(A, D), 구간 안 일별 기여(D−A) 합계 하위 5개 종목, 강제 청산 건수.
- 강제 청산 분류: runBacktest의 `isForcedLiquidation` 거래 중 그 종목의 마지막 거래일이 (데이터 끝 − 14달력일)보다 앞이면 "상장폐지·거래정지 후 강제 청산", 아니면 "기간 끝 미청산 평가".
- 데이터 점검: D 거래의 신호일(매수일)에 PEG 판정에 쓰인 재무 행 = `pickFundamentalsAsOf`(최신 공시)와 `selectEpsCagrFiscalYears`(시작·끝 연도)의 3개 행. 그중 fill/xbrl 소스 행의 rcept_date가 신호일보다 늦은 건수를 센다(null 접수일 행은 로드 단계에서 제외되므로 제외된 행 수를 따로 적는다). "A에서 쓰이지 않았는데 D에서 쓰인 (종목, FY)" = A 거래들의 신호일에 쓰인 (종목, FY) 집합에 없고 D 거래들의 신호일에 쓰인 집합에 있는 쌍을 소스별·연도별로 센다.
- 2021-03~2021-06 월말: 진입 허용(entryAllowed) 구성원 중 PEG 상태가 true인 종목 수(A, D), 그중 그날 해당 변형이 실제로 보유(그날 일별 수익률을 낸 거래가 있음)한 수, 그날 전체 보유 종목 수.
- 이전 결과 대응: 사용자 제시 이전 검증 2021년 수익(+58%)과 A, A2010의 2021년(1월 1일부터, 그리고 3월 1일부터) 수익률을 나란히 쓰고, 시작 인자에 따른 코드 차이는 `lib/backtest.ts`·`lib/strategyBacktestSummary.ts` 줄번호로 인용한다.
