# [임시 점검 — 병합 금지] v3 수익률 상위 거래 데이터 점검 사전 등록 (읽기 전용, 판정 없음, 시도 횟수 미포함, 규칙 변경 금지)

실행 **전에** 커밋한다(커밋 해시는 보고서에 기록). 이후 수정하지 않는다. 기존 규칙·비용·유니버스·집계는 그대로(50/200 골든크로스 + 252봉 고가 −18.29% 이내, 데드크로스 청산, PIT 5천억+거래대금 5억, 수정주가 applied, 비용 반영, 2010-01-01~). 숫자와 표만 보고한다. 브랜치 `claude/ma-v3-portfolio-cap-run`, main 변경·병합 없음, DB는 `stock_price_adjustment_events` 조회만(쓰기 없음).

## 0. 재현 (게이트)
상한 없는 v3: 6.36% / 53.31% / 2,335건(소수 둘째 자리 일치). 어긋나면 중단하고 원인만 보고. 가격은 Parquet 원본(조정 전)을 읽어 종목별로 applied 이벤트를 적용한 사본(조정 기준)을 만들고, 원본 행은 상위 거래 종목에 한해 보존한다(이벤트 적용 방식은 기존 `applyAdjustmentsInPlace`와 동일).

## 1. 청산 방식 분류 (T3 정의)
거래 분류는 `genTrades`가 만든 거래의 청산 인덱스로 한다.
- **데드크로스 청산:** 강제청산 표시가 없는 거래.
- **데이터 끝 강제청산:** 강제청산(데이터 마지막 봉까지 데드크로스 없음)이면서, 그 종목의 마지막 행 날짜가 전체 마지막 거래일 − 14달력일보다 이전(= 상장폐지·데이터 소멸).
- **미청산 평가:** 강제청산이면서 종목의 마지막 행 날짜가 전체 마지막 거래일 − 14달력일 이후(= 현재도 거래 중인 보유 포지션을 마지막 종가로 평가).

## 2. 점검 항목
- **T1:** 비용 반영 거래 수익률 상위 30건(미청산 평가 포함, 거래는 진입일 ≥ 2010-01-01). 종목코드, 진입일, 청산일, 분류, 진입가·청산가(조정 기준 종가 / 원본 종가), 보유일(거래일 수 / 달력일 수), 수익률(비용 반영 %; 원본 종가 단순 수익률 % 병기), 진입일 시총(억, 진입일 행의 market_cap_eok).
- **T2:** 상위 30건 각각: (i) 진입일 초과 ~ 청산일 이하에 event_date가 있는 가격조정 이벤트(status applied/low_confidence)의 건수와 날짜·계수(adjustment_factor)·상태, (ii) 보유 중(진입 다음 행 ~ 청산 행) 연속 행 사이 하루 최대 상승률·최대 하락률과 날짜(조정 기준; 원본 기준 병기), (iii) 보유 중 원본 listed_shares가 직전 행과 달라진 날 수 중 해당 종목의 어떤 이벤트(applied/low_confidence) 날짜와도 일치하지 않는 날 수(전체 변경일 수 병기; 둘 중 하나가 결측·0 이하이면 변경으로 세지 않음), (iv) 보유 구간의 연속 행 사이 달력일 공백이 5일 초과인 구간 수와 최대 공백일.
- **T3:** 전체 거래의 분류별 건수와 평균 수익률(비용 반영 %), 미청산 평가 포지션 수와 평가수익 합(거래 수익률의 단순 합 %, 평균·중앙값 병기), 상위 30건 중 분류별 건수.
- **T4:** 미청산 평가 거래를 모두 제외(해당 거래 일별 기여 제거, 나머지 동일가중 집계 그대로)했을 때 v3 CAGR/MDD/거래 수 — 전체(2010~)/학습(2010~2018)/확인(2019~). 병기로 "미청산 평가 + 데이터 끝 강제청산" 모두 제외한 값도 보고한다(추가 정의일 뿐 선택 기준 아님). 기준(제외 없음) 값과 같은 표.
- **T5:** 집계 경로(기존 `accumulateStockDailyReturns`, 2,335건)와 일반화 경로(감사 스크립트의 `makeTrade`, 2,333건)의 거래 수 차이 2건이 어떤 거래인지(코드, 진입일, 청산일, 진입·청산 인덱스, 종목 행 수)와 일반화 경로가 제외한 사유(코드 조건: 진입 인덱스 ≥ 청산 인덱스 / 가격 ≤ 0 / 일별 수익률 계산 불가)를 거래별로 출력한다.

## 3. 실행·중단 규칙
워크플로 1회만, 재실행 금지. 17개 Parquet 연도 파일이 전부 캐시에 없으면 실행 전에 보고. `[parquet-cache]` 줄과 Supabase 다운로드 MB를 그대로 보고. 판정·추천 없음.

## 4. 한계
상위 30건 후보는 비용 반영 수익률 100% 초과 거래의 종목 행만 보존해 선별하며, 100% 초과 거래가 30건 미만이면 가능한 건수만 보고한다. 이벤트 테이블에 없는 미등록 분할은 T2에서 "이벤트 없이 상장주식수가 바뀐 날"과 하루 최대 등락률로만 간접 확인한다.
