# Supabase 읽기(Egress) 예산 기준 정정과 재집계 (2026-11-22)

연구 브랜치 전용 기록. 연구 DB 쓰기 0, 외부 호출 0.

## 0. 기준 정정 (사용자 지시 2026-11-22)
- **실제 한도는 Supabase 무료 플랜 Egress 5 GB**다. 사용자가 대시보드에서 확인한 값: **Egress 0.463 GB(9%)**, Cached Egress 0.215 GB(4%), Storage Size 0.53 GB(53%), Database Size 0.253 GB(51%). 이 값에는 **운영 앱 트래픽이 섞여 있다**.
- **400 MiB 읽기 예산은 임시 안전선이었으므로 폐기**한다(`forward-data-plan.md` §4.2, `signal-scan-5-collection-plan.md` §11, 각 사전등록의 "Storage 누적 400 MiB 상한" 포함). **새 가드: Egress 4 GB(5 GB의 80%)**. **쓰기 가드 800 MiB(Storage Size 1 GB 대비)는 유지**한다.
- **앞으로의 보고는 추정치가 아니라 대시보드 값을 기준**으로 하고, 큰 작업(예상 읽기 50 MiB 이상 또는 수집 회차 시작·종료) 전후에 사용자에게 대시보드 확인을 요청한다. 로그의 "Storage 내려받기 합계"는 연구 실행분의 하한 참고치일 뿐이다.
- 별도 주의: Database Size 0.253 GB가 무료 한도(0.5 GB)의 51%다(규칙 3: DB 용량 예산). 이번 작업은 DB 쓰기 0이다.

## 1. 이번 청구 주기(11-14~) 연구 Storage 읽기 재집계 (연구 워크플로 98회 로그·문서)

- **대시보드와의 관계**: 연구 합계 약 336 MiB는 대시보드 Egress 0.463 GB(약 474 MiB)의 약 71%다. 나머지 약 138 MiB는 운영 앱 트래픽·연구 실행의 DB 행 읽기(실행당 약 1.5만 행)·미집계 실행으로 보이나 로그로는 나눌 수 없다.
- **미집계 표시**: 프로브 9회, 스캔 5 수집 4회, 저평가 수집 4회의 진행 파일 읽기, 운영 워크플로(스크리닝·시장 지표 등 약 66회)와 앱 트래픽, DB 행 읽기.
- **가드 대비**: 새 가드 4 GB 대비 연구 로그 기준 약 8%(대시보드 전체 기준 11.6%). 사용자가 확인한 대시보드 값 0.463 GB < 3 GB이고 큰 미집계가 없어 이번 시험까지 진행했다(`value3-prereg.md` §7).

## 2. 읽기 절감: 연구 자료 파일 Actions 캐시 (2026-11-22, 커밋 8bfb24d)
- **무엇을**: 시험·점검(`which=batch5`)이 반복해서 읽는 **재무 fin.parquet(14.17 MiB), 2016 이전 재무(0.50), 월말 시장 목록(0.21)** 을 Actions 캐시(키 `research-files-v1-<run_id>`, 복원은 접두 `research-files-v1-`)에서 읽는다. 구현: `lib/researchFileCache.ts`(`RESEARCH_CACHE_DIR`가 있을 때만 동작, 없으면 기존처럼 Storage 직접), 워크플로의 복원·저장 단계(dirty 표시가 있을 때만 저장). **포워드 실행(ds6fwd)에는 쓰지 않는다**(2026 가격 파일이 매일 바뀌고 월말 목록도 최신이 필요).
- **만료 대응**: 캐시는 7일 미사용 시 삭제된다. 키퍼얼라이브 ds12(11-24·12-01·12-08)가 같은 복원 단계를 실행해 사용 기록을 갱신한다. 만료·미스 시 첫 실행이 Storage에서 **14.88 MiB**(fin 14.17 + 2016 이전 0.50 + 월말 목록 0.21)를 읽고 다시 저장한다. 자료 원본이 바뀌면 키 버전을 v2로 올린다(불변 자료 전제).
- **읽기량 로그**: 이제 "Storage 내려받기 합계"에 연구 자료 파일 다운로드를 포함하고 "연구 자료 파일 캐시 적중/다운로드(파일별 MiB)" 줄을 남긴다.
- **검증**(정의·결과 불변, 보정 데이터 기준 정보용 `v2info`): 캐시 미스 run 44992025145 읽기 14.88 MiB → 캐시 적중 run 44992264527 **0.00 MiB**. 두 실행 모두 DS6 11.70 / 39.15, VB1 10.07 / 64.17, DS13L 12.15 / 37.91, VB1F 7.55 / 49.52, DS14 13.84 / 46.05로 이전 결과와 동일했다. 이후 v3pre·v3test·v3info도 읽기 0.00 MiB(캐시 적중)였다.
- **절감 효과**: 시험·점검 1회당 약 14.9 MiB → 0(만료 시 첫 실행만 14.88). 이번 작업 5회에서 약 59.5 MiB 절감. 남는 정기 읽기: 포워드 실행 주 1회 약 16 MiB(주기당 약 65 MiB), 소진율·분봉 월 증분.
- **한계**: 캐시 복원은 Storage 읽기가 아니지만 GitHub 캐시 저장소(저장소당 10 GB)를 약 15 MiB 쓴다. 가격 Parquet 스냅샷(230.92 MiB, 키 `parquet-snapshot-20261026`)은 기존대로 유지된다.
