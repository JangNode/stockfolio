# 연구 PEAD — 실적 공시 직후 드리프트 (PE1 = 시도 235, PE2 = 시도 236, PE3 = 시도 237 예정) 사전등록 (초안 — 사용자 승인 전)

작성 2026-10-27(사용자 지정). **이 문서는 1단계(가능성 점검) 결과와 2단계(시험) 정의를 미리 적어 둔 초안이며, 2단계는 사용자 승인 전에는 실행하지 않는다.** 승인 때 바뀌는 내용이 있으면 시험 실행 전에 이 문서에 추기해 다시 커밋하고 해시를 보고한다. 국내 주식과 현금만 쓴다(ETF 매매 금지, 069500은 기준선 전용). 모든 구간 성적은 개발 데이터 내 성적이다. 연구 브랜치 claude/ma-v3-portfolio-cap-run에서만 작업하고 main 병합은 하지 않는다. 1단계는 시험이 아니므로 시도 번호를 쓰지 않았다(누적 234 그대로).

## 1. 목적

실적 공시(정기보고서)에서 영업이익이 흑자이고 전년 동기보다 크게 늘어난 종목을, 공시 뒤 이틀째 종가에 사서 일정 기간 보유하면 공시 직후 드리프트(PEAD)로 초과수익이 나는지를 기계적으로 판정한다. 공시 시각 정보가 없어 항상 하루 더 늦춰 진입하는 보수적 규칙이다. 먼저 자료로 시험이 가능한지(1단계)를 점검했다.

## 2. 1단계 결과 — 가능성 점검 (시험 아님, 읽기 전용, 가격 성과 계산 없음; 커밋 6e53e90, run 40452995112)

고정 스냅샷(2026-10-26, 매니페스트 SHA-256 17개 일치)과 연구 R이 Storage(`research/r_allcap`)에 모아 둔 `fin.parquet`·`filings.parquet`만 읽었다. 외부 요청 0건, 연구 DB 쓰기 0, 가격 Parquet 다운로드 0. 이번 점검 실행당 Storage 내려받기 15.11 MiB(재무 14.17 + 공시 목록 0.73 + 월말 시장 목록 0.21), 점검을 두 번 돌려 합계 약 30.2 MiB.

### (a) 자료 구조

- **공시 접수일**: `fin.parquet`(171,497행: corp_code, stock_code, bsns_year, reprt_code, fs_div, rcept_no, rcept_dt, status[orig 152,287·corr 19,206·unk 4], 매출·영업이익·순이익·자산·부채·자본 열)과 `filings.parquet`(132,380행: corp_code, rcept_no, rcept_dt, correction[N 102,613·Y 29,767], report_nm)에 접수번호·접수일(`rcept_dt`, 날짜만)이 있다. **접수 시각·장중/장마감 후 구분 열은 없다**(DART 목록 API가 날짜만 주고 수집 열에도 없음).
- **수집된 공시 종류**: 정기공시(분기·반기·사업보고서와 그 제출기한연장신고서)뿐이다. 영업(잠정)실적 공정공시 등 정기보고서보다 먼저 나오는 실적 공시는 수집돼 있지 않다 — 즉 "접수일"은 정기보고서 접수일이고, 일부 기업의 실적이 그 전에 이미 공개됐을 수 있다.
- **기간**: 영업이익 값이 있는 분기 데이터(1분기·반기·3분기)는 **사업연도 2016부터**(첫 접수 2016-04-12), 사업보고서는 사업연도 2015부터(접수 2016-05까지 포함)다. 사업연도 2014 이전은 `fin.parquet`에 없다. 분기 영업이익·전년 동기 값이 모두 있는 원본 접수 이벤트는 접수 연도 2016 4,896건, 2017 6,424건, … 2025 9,346건, 2026(~10-23) 6,945건, 합계 81,643건(유니버스 무관). **2011~2015 접수 이벤트는 0건.**
- **영업이익 정의(연구 R 정의 그대로, `lib/rFinMetrics.ts` `quarterOi`)**: 1분기·반기·3분기 보고서는 당분기(3개월) 영업이익과 전년 동기 영업이익, 사업보고서는 연간 − 3분기 누적(전년도도 같은 방식). 연결(CFS) 우선, 없으면 별도(OFS), 둘을 섞지 않는다. 값 채움률 99% 안팎(사업연도 2016~2017 보고서 종류별 oi_c 97.7~100%, oi_p 96.7~99.2%).
- **정정공시**: 정기공시 접수 중 정정(Y)이 29,767건(22.5%). fin.parquet은 (회사, 연도, 보고서, 연결/별도)마다 한 줄이라 정정되면 정정 후 값이 그 줄에 들어가고 **정정 전 원본 값은 보관돼 있지 않다**(상태 corr 행 19,206개에 값 있음). 비정정 접수 102,613건 중 접수일 시점에 값이 하나라도 있는 이벤트로 남은 것은 84,148건(82.0%), 분기 영업이익·전년 동기 값이 모두 있는 것은 81,643건(79.6%)이고, 나머지 약 18%는 접수일 시점 값이 "자료 없음"이다(정정으로 대체된 보고서 등). 연구 R의 정정 점 시점 규칙은 정정 접수일에 정정 후 값으로 다시 계산한 이벤트 8,195건을 덧붙이는데, **PEAD에서는 이것을 새 이벤트로 세지 않고 원본(비정정) 접수 이벤트만 신호로 쓴다**(정정은 새 실적 소식이 아니므로).

- 2011~2015 접수 이벤트가 0건이라 **학습 구간(2011~2016)은 2016년 한 해뿐**(후보당 진입 22~30건)이다. 이를 채우려면 DART 다중회사 주요계정 API가 닿지 않는 2015년 이전 보고서의 원문(document.xml)을 받아 영업이익 표를 직접 파싱해야 한다(재무 API의 제공 범위가 2015년 이후라는 점은 이번 수집 결과에서도 확인됨: 분기 값은 사업연도 2016부터).
- **추정(실측 아님, 가정 표기)**: ① 2011~2013 정기공시 목록(list.json, 연구용 키): 대상 corp_code 최대 약 3,500개 × 1~2쪽 ≈ 3,500~7,000건. ② 2011-01~2015-12 접수 정기보고서 원문: 2014~2026 평균 연 약 8,000건(전 시장) 기준 5년 약 40,000건, 코스피만이면 약 18,000건(코스피 비중 약 45% 가정). 원문 1건 zip 0.3~2 MB 가정 → 내려받기 약 5~80 GB(저장은 하지 않고 파싱 결과 약 2~5 MB Parquet만 Storage에 추가). ③ 연구용 키 2개(키당 하루 18,000건, 총 100,000건 상한; 연구 R 기록상 누적 8,403건)로는 약 2~3일에 나눠 돌려야 한다. ④ 파싱 정확도는 2016~2017 보고서에서 API 값과 대조해 검증할 수 있지만 2011~2014 서식(K-IFRS 도입 직후) 편차는 미지수다.
- 승인 전에는 수집하지 않으며, 수집한다면 먼저 20건 이내 파일럿으로 원문 크기와 파싱 일치율을 재고 보고한다.

## 3. 2단계 정의 (사용자 지정 규칙을 그대로 옮김, 승인 후 실행)

- 시도 번호 235부터(누적 234 이어서): PE1 = 235, PE2 = 236, PE3 = 237(1단계에서 실행 불가로 정리하는 후보는 번호를 쓰지 않는다).
- **이벤트**: 실적 공시(정기보고서)에서 영업이익 > 0, 전년 동기 영업이익 > 0, 전년 동기 대비 증가율 ≥ 기준. 증가율 = 영업이익 ÷ 전년 동기 영업이익 − 1. 원본(비정정) 접수만 이벤트로 센다(해석, 2절 (a)).
- **신호(보수적)**: 접수일 다음 거래일 종가에 신호 확정, 그다음 거래일 종가에 체결(공시 시각 정보가 없으므로 항상 하루 더 늦춤). 신호 확정일 종가가 접수일 종가보다 높은 경우(수익률 > 0)만 매수. 접수일이 거래일이 아니면 그 뒤 첫 거래일을 접수일로 본다(해석).
- **보유**: 체결 후 고정 N거래일 보유, 그다음 거래일 종가 매도(손절·익절 없음). 동시 보유 최대 10종목, 종목당 10%(체결 시점 계좌 가치의 10%), 남는 몫은 현금. 같은 종목 재진입은 보유 종료 후 20거래일 금지. 후보가 남은 슬롯보다 많으면 영업이익 증가율 큰 순(동률은 코드 오름차순). 남은 슬롯이 없는 날의 후보는 버린다(이월 없음, 해석).
- **후보(조정 금지)**: PE1 = K200P, 증가율 ≥ 30%, N = 40. PE2 = SMALL, 증가율 ≥ 30%, N = 40. PE3 = K200P, 증가율 ≥ 50%, N = 60.
- **공통**: 코스피 보통주 PIT 유니버스(신호 확정일 기준 월말 구성 + 당일 시총·유동성), 비용 0.015%/편도 + 매도세, 슬리피지 0.1%(SMALL은 0.2%), 상장폐지 강제 청산, 구간 학습 2011~2016 / 확인 2017~2021 / 보류 2022~, 게이트 A~H 기존 정의(G 100건 완화 금지, B는 세 구간 중 2개 이상, 기준선은 새 069500 7.42/42.03), 국내 주식 + 현금만, 결과를 본 뒤 정의 변경·재실행 금지.
- **게이트 D 이웃**: 증가율 ±10%p, N ±20거래일(후보당 4개): PE1·PE2 = 증가율 20%·40%, N 20·60; PE3 = 증가율 40%·60%, N 40·80. 이웃은 전체 구간 CAGR ≥ 069500이면 통과.
- **게이트 H**: 기준선 = 069500(새 기준선). 조건1 = 후보 전체 CAGR ≥ 069500 + 1%p, 조건2 = 후보 MDD ≤ 069500 − 3%p 이고 CAGR ≥ 069500 − 1%p. MDD 5%p 이상 개선은 표시만.
- **게이트 F(해석, 사용자 지정 없음)**: 같은 신호일·같은 주문 수로, 그날 유니버스 안 "분기 영업이익·전년 동기 비교 가능한 원본 접수 이벤트 중 접수일 종가 대비 신호 확정일 종가 수익률 > 0인 종목"을 무작위로 뽑아(영업이익 흑자·증가율 조건 없음) 같은 보유·크기 규칙으로 다시 돌린다. 1,000회, 시드 20261022. 풀이 주문 수보다 작으면 있는 만큼만 뽑는다. 백분위 ≥ 95.
- **게이트 E**: 닫힌 거래 중 거래 기여 상위 3개를 같은 진입·청산 실행일 동안 069500으로 바꿔 CAGR ≥ 069500. **게이트 G**: 전 기간 진입 100건 이상. **게이트 C**: lag 2(체결·매도 하루 더 지연) 전 기간 CAGR 하락 ≤ 1%p, MDD 악화 ≤ 2%p. **게이트 A**: 전 기간 CAGR ≥ 069500 + 2%p ∧ MDD ≤ 069500 MDD. **통과** = A~H 전부 O.
