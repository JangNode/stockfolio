# CR1 확인 — 별도 시도 (누적 시도 136) 사전등록

CR1은 1b6bf3f에서 학습 G1~G4 전부 O였으나 선택 규칙(자기 기준 대비 초과 최대)으로 CR3가 선택돼 확인을 계산하지 않았음. CR3 확인 실패(bf9516a 실행) 후 CR1을 별도 시도로 확인함. 같은 신호의 MID 버전 실패를 안 상태라는 점을 한계로 기록. 정의·비용·기준(G1 ≥ POOL + 1.0%p, G2 > B&H, G3 MDD ≤ POOL + 5.0%p, G4)·R1~R3는 1b6bf3f와 동일.

## 절차

확인(2017-01-01~2021-12-31) → 전부 O면 홀드아웃(2022-01-01~) → 전부 O면 R1~R3. X면 그 단계에서 종료.

## 구현 메모

- 스크립트 `scripts/research-credit-tilt-cr1.ts`는 `scripts/research-credit-tilt.ts`(bf9516a)를 복사해 학습 선택 단계만 빼고 선택을 CR1(비교 기준 POOL)로 고정한 것이다. 엔진·유니버스·C1·3등분·가중치·비용·지연 변형·R1~R3 코드는 바꾸지 않는다.
- 학습 구간은 1b6bf3f 실행(bf9516a)에서 이미 계산했으므로 다시 계산하지 않는다.
- 홀드아웃까지 계산하게 되면 기존 관례(홀드아웃 실행 시 누적 시도 +1)대로 137로 센다. 이 경우 위성 전략 v1의 번호가 하나 밀리는 점은 보고 때 따로 알린다.
- 외부 요청 0, DB 쓰기 0, 1회 실행, 재실행 없음.
