## 2. 구성

- `lib/ds6ForwardConfig.ts` — 고정 날짜·기록값·정의 커밋·KRX 상한(25)·다운로드 허용 연도 등 상수.
- `scripts/research-ds6-forward.ts` — 계산 본체(DS6 시뮬레이터는 `scripts/diagnose-ds6-followup.ts`의 코어·LV1·합성 코드를 정의 변경 없이 옮김).
- 워크플로 `diagnose-benchmark-reference-implementation.yml`의 `which=ds6fwd`(**workflow_dispatch 전용, 스케줄 없음**). 새 Actions 캐시 항목은 만들지 않는다.
- 로그 `docs/research/ds6-forward-log.csv` — KB 단위. 매 실행마다 관찰 구간 전체를 다시 계산해 덮어쓴다(069500 종가 기억을 겸한다).

### 두 단계 (한 실행 안에서 순서대로)

1. **검증 단계**(고정 스냅샷, `PARQUET_CACHE_FROZEN=1`, `RESEARCH_DATA_END=2026-10-26`): 고정 구간을 다시 계산해 기록값과 2자리 반올림이 같은지 본다. **다르면 거기서 멈추고(관찰 단계로 넘어가지 않음) 보고한다.** 통과하면 고정 구간 일별 수익을 `.ds6fwd/`에 임시 저장한다.
2. **관찰 단계**(라이브): 가격 Parquet을 복원한 캐시 그대로 읽는다. Storage 메타데이터 조회(가벼운 목록 API) 결과 캐시와 다른 연도가 있어도 **2025·2026만** 받는다(그 밖의 연도가 다르면 받지 않고 중단). 계산 결과의 고정 구간이 다시 기록값과 같아야 하고(다르면 중단), 검증 단계 일별 수익과의 차이는 정보로만 출력한다. 이어서 2026-10-27 이후 DS6·069500 일별 수익, 누적, 초과, 낙폭을 CSV로 쓴다.

KST 14:00~15:40에는 시작 즉시 종료한다(아무것도 읽지 않음). 키 값은 출력하지 않는다. DB 쓰기·Storage 쓰기 0.

## 3. 읽는 데이터와 Storage 읽기량

| 상황 | Storage 읽기 |

## 4. 069500 종가 확장 (보조 파일 2026-10-26 이후)

보조 파일(`research-aux-069500-20261026`, SHA-256 `336fdcd99cd8…`)은 2026-10-26까지다. 그 뒤 거래일(가격 Parquet 달력 기준)의 종가는 다음 순서로 찾는다.

1. `docs/research/ds6-forward-log.csv`에 이미 있는 날짜 → 그대로 쓴다(외부 호출 없음).
2. DB `etf_daily_prices.raw_close`에 있으면 그것(DB 읽기).
3. 둘 다 없는 날짜만 KRX `etp/etf_bydd_trd`를 하루 1회 호출(요청 간격 300 ms, **이번 관찰 실행 상한 25회**; 다른 연구 실행의 기본 상한 12는 그대로). `KRX_API_KEY`는 GitHub Secrets에서만 읽는다.

KRX가 마지막 거래일 자료를 아직 내지 않았으면(응답 0행) 그 날짜부터는 비우고 관찰 구간을 앞 날짜까지로 자른다(중간이 비면 069500 수익이 잘못 이어지므로 건너뛰지 않는다). 로그에 `close_src`(db/krx)가 남아 다음 실행부터는 호출하지 않는다. 한 달 치(약 21거래일) 신규 호출이 필요한 달에는 호출 수가 최대 약 21회다.

## 5. 로그 CSV 열

`date, ds6_ret_pct, b069500_ret_pct, ds6_cum_pct, b069500_cum_pct, excess_cum_pp, ds6_dd_pct, b069500_dd_pct, b069500_close_raw, close_src, core_hold, month_end_class_date`

- 누적은 고정 날짜 종가 기준(%), `excess_cum_pp = DS6 누적 − 069500 누적`, 낙폭은 관찰 구간 안 고점 대비(≤0, %).
- `core_hold` = 코어가 든 종목:코어 안 비중(%) 목록.
- **`month_end_class_date` = 그 날짜에 쓴 월말 시장 구분 스냅샷 날짜(마지막 월말 구분 날짜).** 현재 마지막은 **2026-10-23**이고 그 뒤 월말 구분은 반영되지 않는다. 월말 구분 수집기(KRX Open API)는 이 도구가 돌리지 않는다. 실행 요약에도 같은 날짜를 매번 적는다.

## 6. 월 1회 직접 실행하는 방법

1. GitHub → Actions → "벤치마크 참조 구현 재실행 (검증, 영구 보존)" → Run workflow.
2. **Use workflow from = `claude/ma-v3-portfolio-cap-run`** (연구 브랜치), `which = ds6fwd` 입력. 나머지 입력은 비운다.
3. KST 14:00~15:40을 피해서 실행한다.
4. 끝나면 워크플로가 `docs/research/ds6-forward-log.csv` 한 파일만 같은 연구 브랜치에 커밋한다(`commit-ds6-forward-log` 작업, main·PR 아님). 실행 요약 한 줄은 잡 요약(Summary)과 로그 끝에 나온다.
5. 커밋 작업이 실패하면(권한·충돌) 아티팩트 `ds6-forward-log`(90일 보관)에 같은 파일이 있다. 다음 Claude Code 세션이 그 아티팩트를 받아 연구 브랜치에 커밋한다. 직접 커밋할 필요는 없다.

중단 신호: 검증 단계 "불일치", 캐시 게이트 차단, KRX 상한 초과, KST 금지 시간대, 허용 연도 밖 다운로드 필요 — 모두 로그를 쓰지 않고 실패로 끝난다. 그 경우 결과를 보고하고 지시를 받는다.

## 7. 한계 (매번 표시할 것)

- 월말 시장 구분은 2026-10-23 스냅샷 기준이다(위 5절). 이후 월말 편입·이탈은 코어 후보 목록에 반영되지 않는다.
- Actions 캐시(`parquet-snapshot-20261026`, `research-aux-069500-20261026`)는 7일 이상 쓰지 않으면 삭제된다. 월 1회 실행이면 만료돼 있을 수 있다. 그 경우 게이트가 막고(Storage 읽기 0) 231 MiB 재구축은 별도 승인 없이 하지 않는다.
- 라이브 데이터는 고정 스냅샷 이후 수정(조정 이벤트, 정정 행)이 반영될 수 있다. 고정 구간이 기록값과 어긋나면 중단하고, 일별 차이는 정보로 출력한다. 069500 일수익률의 스파이크 정제(`ETF_SPIKE_*`)는 다음 날이 생기면 전날 값이 바뀔 수 있어 매 실행에서 전체를 다시 계산하고 달라진 행 수를 출력한다.
- 관찰 구간은 짧을수록 의미가 작다. 표본 수와 무관한 순위·판정 문장을 만들지 않는다.
